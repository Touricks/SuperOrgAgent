# 台账

飞书项目记一件事走到了哪一步，飞书文档记这件事的内容。所有读写都走项目里的 `.claude/agent-org/bin/ledger.py`：它按规则文件里的英文标识找类型和字段，按 `feishu/field-dictionary.json` 把中文选项换成选项 ID，不凭中文名猜。

台账结构（六种工作项类型、状态和流转表单、字段、文档放在哪里）见 `references/structure.md`；命令的完整用法和输出见 `references/commands.md`。

## 读：谁都能用

```bash
python3 -I .claude/agent-org/bin/ledger.py get <工作项 ID>        # 类型、状态、名称和有值的字段；--raw 看原始输出，里面没有决定人这类人员字段的值
python3 -I .claude/agent-org/bin/ledger.py query queue        # 决策队列：待决定的决策
python3 -I .claude/agent-org/bin/ledger.py query blocked      # 阻塞的同序列需求
python3 -I .claude/agent-org/bin/ledger.py query verifying    # 待验收
python3 -I .claude/agent-org/bin/ledger.py query reviewing    # 待核查的送审
python3 -I .claude/agent-org/bin/ledger.py query open --sequence alg
python3 -I .claude/agent-org/bin/ledger.py query cross        # 进行中的跨序列需求
python3 -I .claude/agent-org/bin/ledger.py query source:<ID>  # 由某个工作项引出的工作项
python3 -I .claude/agent-org/bin/ledger.py trace <工作项 ID>  # 沿来源工作项往回查，追到引出它的决策
python3 -I .claude/agent-org/bin/ledger.py status <工作项 ID> # 主文档的状态包
python3 -I .claude/agent-org/bin/ledger.py mql queue          # 只打印 MQL
```

每个状态流都自带“已终止”，视图默认不显示它，这里的查询也都排除了它。查询每页 50 项，多的自动翻页；输出读不懂时停下报错，不当成空结果。

文档用 `lark-cli docs +fetch --doc <链接> --as user` 读。先读大纲（`--scope outline --detail with-ids`）拿到块 ID，再只读需要的那一节（`--scope section --start-block-id <ID>`），省上下文。

## 写：只有书记员

每条写命令先不加 `--apply` 跑一遍，核对打印出来的 meegle 和 lark-cli 命令，再加 `--apply` 执行。

| 要做的事 | 命令 | 会做什么 |
| --- | --- | --- |
| 登记需求包、送审包、决策包、立项单 | `register <草稿> [--source <ID>] [--set 标识=值] [--resume] [--doc <链接>\|new]` | 先检查草稿、父节点、模板 ID 和必填字段（发出方、序列、关系、来源工作项等），有一样不行就不建；选填字段（截止时间、紧急程度、建议等）转换不了就跳过并提醒，之后用 update 补；用 `--set` 传的值转换不了，会停下报错。建工作项，并把研究员填进“研究员”角色，建完读“当前负责人”核对，没有研究员就补，读不到就提醒；按规则把主文档上传到对应节点，补“状态包”和“交接记录”；主文档的 `/wiki/` 链接写回工作项；加一条登记评论；把工作项 ID 写回草稿。回执 `packages/sent/<ID>.json` 在工作项建好时就写下，中途失败了，修好原因后加 `--resume` 接着做，不会再建一个。执行关系的需求包要有来源工作项（`--source` 或包里写“来源工作项 #ID”），关系要和发出方职级一致 |
| 登记交付包、验收包 | `reply <草稿> [--doc <链接>\|new]` | 上传到它答复的那份主文档下；交付包的链接写进“交付包”字段；验收包打印接下来的流转命令（送审还在“待核查”时，先加一条流转到“核查中”） |
| 流转 | `transition <ID> <目标状态> --set 标识=值` | 检查这一步在规则里允许、空间里也给了这条流转；必填项以空间的流转表单为准，规则文件写的表单只用来对照，不一致时提醒报给研究员（离线时才按规则文件检查）。先写字段，再按空间给的 ID 流转，回读状态。流转到“阻塞”自动写阻塞开始日期；“已终止”不是流转，要研究员在网页上操作 |
| 改字段 | `update <ID> --set 标识=值` | 选项按名称换成 ID，日期写 UTC 中午 |
| 评论 | `comment <ID> --text '...'` | 开头没有会话标签的自动补 |
| 替换状态包 | `status-block <ID> --file <文件>` | 找到主文档里“状态包”到“交接记录”之间的块，整段 block_replace |
| 追加交接记录 | `append <ID> --file <文件>` | 第一行要带会话标签；追加到文末 |
| 归档 | `archive <ID>` | 把主文档整棵子树移到“归档文档/<序列>”下，移动的是原节点，链接不变；没有这个序列的归档节点就停下，先 ensure-node；之后再流转到“归档” |
| 建知识库节点 | `ensure-node <键>` | 比如 `feedback`、`review/alg`。先用 `wiki +node-list` 查上一级节点下有没有同名的节点，有就直接用；没有才建。都写进 `feishu/ids.json` |

几条规则：

- 执行关系的需求包按验收标准划分，不按运行次数划分；每次运行的 ID 写进“运行 ID”字段。
- 待验收的同序列需求，要等验收包出来才流转到“已验收”或退回“执行中”。
- 决策：队列来的建成“待决定”；研究员主动发起的建好后直接流转到“已决定”，表单填决定内容和决定人。
- 写入连续失败两次就停，不换着法子重试；把命令、报错原文和 logid 写进交回的异常清单。
- 字段还没绑定（`feishu/ids.json` 里没有它的 field_key，`feishu/migration.md` 的“要处理的问题”里列着）：登记时的选填字段会跳过并提醒；用 `--set` 传这种字段、或者离线流转要求它时，会停下报错。请研究员在网页上补好（先补模板空间，再补本空间），或者用 `--map` 指认空间里名字不同的字段，再跑 `setup.py feishu --live --apply`。不要拿别的字段顶替。
- 台账脚本说“还没绑定飞书空间”，或者任务文件里的空间和绑定的不同：交回请求方，请研究员按 `agent-org:setup` 的第四步绑定，书记员不代跑。
- 决定人这类人员字段只能填“研究员”：所有 agent 用的是研究员一个账号，也只有研究员拍板。
- `feishu/ids.json` 里已经有项目的，立项单加 `--existing` 挂到那个项目上，`--set` 的字段一并写进去，不会再建一个项目。立项单改过要换主文档的，修订版另存成新的草稿文件再登记；登记过的文件不能再登记。
- 同序列需求登记后停在“待开工”。登记请求写了“开工”的（请求方马上派下一级），接着 `transition <ID> 执行中`；排队没派的等请求方说开工再流转。
- `--set 标识=@文件` 读文件内容，先按当前目录、再按项目目录找。找不到时，只要它像文件名（一个词，或者带 /、扩展名、<占位符>）就停下；中间有空格的文字（`@研究员 还没批预算`）照原样写。要写以 @ 开头的文字，用 `@@`。
- 建文档超时、或者返回里没有链接时，文档可能已经建好了，回执记下“没有确定结果”，重跑会停下。先到提示里的节点下核对：建好了的，加 `--doc <文档链接>` 接着用它；确认没建成的，加 `--doc new`。

## 拿不准时

- 草稿通不过检查：退回请求方，附上检查输出，不替作者改内容。
- 来源工作项不存在、已关闭：不登记，交回请求方确认。
- 台账和文档对不上：两边都不改，写进异常清单交给路由。
