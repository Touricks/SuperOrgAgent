# 路由决策表

逐条往下判，命中就停；判断不了就上交，不猜。路由的质量更多取决于输入是否规范：包名带作者的会话名、工作项有来源字段，这两条约束比路由提示词写得多巧更重要。

| 行 | 收到什么 | 判据 | 动作 | 谁来判 |
| --- | --- | --- | --- | --- |
| R1 | 带工作项 ID 或会话名的信息 | ID 存在，工作项未关闭 | 在该工作项下加带会话标签的评论，恢复负责会话；该序列开着聚焦会话的，交给聚焦会话 | 脚本 |
| R2 | 没带 ID 的补充信息 | 按工作项名称、字段和状态包只匹配到一项进行中的工作 | 同 R1，并在评论里写明匹配依据 | 路由 +1 |
| R3 | 没带 ID 的补充信息 | 匹配到多项，或一项也没有 | 交项目管理 +2 判断 | 脚本或路由 |
| R4 | 新任务 | 无 | 交项目管理 +2；研究员拍板后，由对应序列的 +2 发需求包 | 入口 |
| R5 | 需要人拍板的事 | 无 | 建“待决定”的决策工作项，渠道填决策队列，进决策队列 | 入口；交回的决策包由脚本识别 |
| R6 | 聚焦会话交回的决定 | 状态是“已决定” | 建决策工作项并直接流转到“已决定”，渠道填研究员主动发起，通知受影响工作项的负责会话 | 脚本 |
| R7 | 各序列交回的包 | 按包类型和关系 | 照包的流向转交 | 脚本 |

## 脚本怎么判

`route.py classify --text`：

- 找工作项 ID（`#` 后面的数字，或九到十二位的长数字）和会话名（如 `Alg-p1-02`、`Alg-p0-2003`；+0 的会话名里带工作项 ID）。
- 有 ID 的，读台账：存在且未关闭，命中 R1，输出负责会话，和这个序列是否开着聚焦会话；不存在或已关闭，输出 R3。
- 只有会话名的，命中 R1，输出这个会话的角色。
- 都没有的，输出 `needs_router`，候选是 R2 到 R5。脚本不按关键词猜“新任务”或“要拍板”，这些交给模型判断。

`route.py classify --draft`：先跑包检查，通不过就退回作者；然后按包类型和关系判 R5、R6、R7，输出下一跳和步骤。

| 交回的包 | 行 | 下一跳 | 步骤 |
| --- | --- | --- | --- |
| 跨序列的需求包 | R7 | 承接方序列的 +2 | 书记员建跨序列需求（待接单）；派承接方接单 |
| 跨序列的交付包 | R7 | 发起方序列的 +2 | 确认结论已有验收包；书记员挂答复、流转到“已交付”；恢复发起方 |
| 送审包 | R7 | quality-p2 | 书记员建送审（待核查），被送审的工作项流转到“待验收”；派质量 +2 |
| 验收包 | R7 | 书记员 | 书记员挂答复、按提示流转两处；恢复送审方所在序列的 +2 |
| 决策包，渠道是决策队列 | R5 | 书记员 | 建成“待决定”；“插队”的马上交研究员 |
| 决策包，渠道是研究员主动发起 | R6 | 书记员 | 建好直接流转到“已决定”；通知受影响的会话 |
| 下发、执行关系的包 | 无 | 无 | 序列内的包不经过入口，退回作者 |

## 路由 +1 怎么按状态包匹配

1. `ledger.py query open`（必要时加 `--sequence`、或查 `cross`）列出进行中的工作项和它们的名称。
2. 对候选逐个 `ledger.py get <ID>` 看字段（发出方、负责会话、来源工作项等），`ledger.py status <ID>` 读主文档的状态包。
3. 原话里提到的会话、角色、工作项、决策、文档、数据集、版本或节点，和某一项的名称、字段或状态包对得上的，记为匹配。
4. 只匹配到一项：R2，依据写清对上的是哪一条。匹配到多项或一项也没有：R3 上交。不要因为“最像”就选一个。

## 例子

这些例子也是路由测试集的种子：每条写明应当命中哪一行。真实运行时，把研究员的原话和实际路由结果追加进 `org/routing-log.md`，误路由的单独标出，用来量路由准确率。

| 研究员的原话 | 应当命中 | 理由 |
| --- | --- | --- |
| “#2101 的访谈记录我补到文档里了” | R1 | 带工作项 ID，未关闭 |
| “Alg-p1-02 那边的消融跑完了吗” | R1 | 带会话名 |
| “规格 v2 里的种子数改成 5 个” | R2 或 R3 | 没带 ID；规格 v2 只出现在一项进行中的工作的名称、字段或状态包里才是 R2 |
| “导师说下周想看和人工基线的对比” | R2 或 R3 | 没带 ID，要对照名称、字段和状态包匹配；对不上就上交 |
| “再开一个方向：试试用 LLM 生成特征” | R4 | 新任务，研究员拍板后交算法 +2 |
| “要不要追加 100 GPU 小时” | R5 | 超预算，研究员拍板 |
| 聚焦会话交回的“停止条件从搜索开始计时” | R6 | 渠道是研究员主动发起 |
| 算法 +2 交回的跨序列需求包 | R7 | 转给承接方 +2 |
