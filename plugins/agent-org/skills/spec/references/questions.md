# 访谈问题单

每节列出要弄清的问题，以及先去哪里查。查得到的先查，查不到的才问研究员。

## 实验规格

### 一句话

- 这个实验改什么、为了提高哪个指标、在多少预算内？
- 先查：立项单、需求文档的成功判据。

### 可改范围

- 能改哪些东西：代码模块、配置、超参、提示词，还是模型权重？改到什么程度，能不能换模型结构、加依赖？
- 哪些文件即使落在可写路径里也不能碰：评测脚本、数据、依赖锁定文件、随机种子的来源？
- 一个候选是什么：一个 git 快照、一份配置，还是一组权重？要附什么说明？
- 从哪个版本起步？它按评测协议跑出的分数是多少？
- 能用哪些依赖和外部服务？能不能联网下载？
- 先查：代码库的目录结构、训练和评测的入口、依赖锁定文件、git 历史、已有的运行记录。

### 目标指标

- 指标叫什么，越高越好还是越低越好，在哪个划分上算？
- 多个种子或多次重复怎么合成一个分数？
- 提高多少才算数？用什么检验或置信区间判断？比较的两边是不是同一版评测集？
- 哪些指标不能变差，容许多大幅度？
- 优化时看哪个分数，最终报告用哪个，由谁在什么时候跑？
- 先查：评测脚本输出哪些指标、已有的基线结果、需求文档里的成功阈值。

### 实验资源

- 用什么计成本：GPU 小时、API 费用、token、墙钟时间？评测本身的花费，比如 LLM 评审的 token，算不算？
- 单个候选最多用多少？整个项目、每个阶段最多用多少？
- 谁来计量、记在哪里？计时从哪一步开始、到哪一步结束？
- 超了谁叫停？追加预算要谁签字？
- 先查：集群或云账号的配额、API 的计费方式、已有运行记录里一次运行的耗时和花费。

### 搜索方法

- 外层怎样生成候选、怎样挑下一个要扩展的候选、什么时候停？
- 失败的候选怎么记？
- 先查：已有的搜索代码和运行记录。

## 评测协议

### 一句话

- 用什么数据、怎么打分、优化过程中谁能看到什么？

### 这个分数代表什么

- 分数回答什么问题？对哪些场景、哪些用户有效，哪些场景不适用？
- 先查：立项单的目标、需求文档里的用户判据。

### 数据

- 数据从哪里来、有多大、怎么标注、标注质量如何？
- 已知有哪些问题：噪声、重复、分布偏移？
- 先查：数据文件的条数和字段、数据说明、标注规范。

### 存放和版本

- 每份数据放在哪：项目里的路径，还是别的系统？正本在哪？
- 版本怎么定：本地文件的校验和，还是那个系统里固定的版本号？
- 谁能改，改了怎么定新版本、要谁签字？
- 先查：数据目录、文件的校验和（比如 SHA-256）、存放数据的系统里的版本记录。

### 划分和可见性

- dev、test 怎么划：用哪个脚本、哪个随机种子？按时间、按用户，还是随机划？
- 外层优化器能看到什么：dev 的汇总分数、逐条结果，还是都看不到？
- test 由谁、在什么时候跑？结果给谁看？
- 怎么防泄漏：去重、按时间切分、检查训练数据里有没有评测数据？
- 先查：划分脚本、数据里的时间字段和 ID 字段、已有的去重记录。

### 接入方式

- 评测入口是什么命令？
- 在别的系统上跑评测的：被测对象、字段映射、提示词、生成参数、并发和重试在那里怎么设？
- 先查：评测脚本的参数、已有的评测配置。

### 打分

- 指标怎么算、怎么聚合？
- 用 LLM 评审的：评审模型和提示词是哪个版本？和人工标注的一致性测过没有？
- 先查：打分代码、评审模型和提示词的版本。

### 重复和不确定性

- 重复几次、种子怎么定？置信区间或标准误怎么算？
- 先查：已有结果的方差、评测脚本的种子参数。

### 证据标准

- 什么样的结果能当结论用：要附哪些证据（运行 ID、逐条输出、复现命令），核查到什么深度？
- 先查：组织规则里质量序列的核查深度（`org/org.md`）。

### 成本

- 跑一次完整评测要多少时间、多少钱？
- 先查：一次评测运行的耗时和 token 用量。

### 运行记录

- 每次评测要记下什么：代码 commit、配置、数据版本、实验 ID？逐条输出放在哪？
- 先查：`runs/README.md` 里定的运行记录格式。

### 已知局限

- 这个协议测不到什么？已知有哪些偏差？
