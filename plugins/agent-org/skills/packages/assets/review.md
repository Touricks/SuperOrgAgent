# 送审包模板（非质量序列的任一级 → 质量 +2）

执行结果先送质量 +2，请它判断结论能不能信。质量 +2 按用途决定核查深度，再下发给质量 +1。拿到验收包之后，送审方才把交付包交给需求包的发出方。

- 关联工作项：<新建的送审工作项；来源工作项，即被送审的工作项>

## 填写规则

- 只给结论和证据，不写推理过程和说服性文字。质量序列要隔离上下文；大模型当评审时，也会被冗长的论证带偏。
- 完整台账必填。只报排名第一的候选，分数会系统性偏高。
- 已知弱点要主动写。核查中发现的、送审方知道却没报的弱点，会在验收包里单独标出。
- 用途要写实。用途越往外，适用的证据标准越严。

## 按结论类型补充的证据

| 结论类型 | 典型来源 | 必须补充的证据 |
| --- | --- | --- |
| 效果类 | 算法 | 基线及其预算、重复次数和波动、留出集、成本变化 |
| 采纳类 | 产品 | 使用日志、合入记录、用户原话、观察期，以及没用起来的反例 |
| 可复现类 | 工程 | 重跑命令、环境版本、允许的误差、实际重跑结果 |
| 约束有效类 | 基础设施 | 越权测试的步骤和结果、覆盖的约束清单、没有覆盖的部分 |
| 交付完整类 | 各序列 +0 的常规产出 | 每条验收标准对应的证据链接 |

## 各序列的送审要点

| 序列 | 通常送审的内容 | 常见的核查深度 |
| --- | --- | --- |
| 产品 | 试点结论；调研材料的完整性 | 试点结论完整核查；调研材料形式核查 |
| 算法 | 用于决策的方法结论；阶段结果 | 用于试点的结论完整核查；阶段结果抽样复核 |
| 工程 | 可复现性；代码交付 | 可复现性抽样复核；代码交付形式核查 |
| 基础设施 | 约束有效性 | 首次配置时完整核查，之后改动时抽样复核 |
| 项目管理 | 一般不送审；要对外引用的统计才送 | 抽样复核 |
| 外联 | 不送审；材料里的结论必须来自验收包 | 不适用 |
| 质量 | 不送审；争议用决策包交 +3 | 不适用 |

核查深度由质量 +2 决定：形式核查只看证据是否齐全、能否追溯；抽样复核挑部分证据重跑；完整核查包括复现、留出集重评和红队检查。
