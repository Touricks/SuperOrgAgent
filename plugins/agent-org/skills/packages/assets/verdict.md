# 验收包模板（质量 +2 → 送审方及其上一级）

质量 +2 答复送审包。送审方据此知道结论能怎么说、还要补什么；送审方的上一级据此接收交付包。

## 模板

```markdown
# 验收包：<结论简称>

- 包类型：验收包
- 发出方：质量 +2（会话 ID）
- 接收方：<送审方的序列和职级>，抄送其上一级
- 关联工作项：<送审工作项；来源工作项>
- 需要接收方做的事：按可使用的原文更新交付包；处理后续要求
- 回复期限：
- 上下文范围：可以按事实依据继续检索

## 结论
<接受、缩小或否决，一句话。>

## 可使用的结论原文
<下游，包括外联序列，只能用这一版。>

## 核查深度
<形式核查、抽样复核或完整核查，以及依据的证据标准条目。>

## 核查摘要
| 核查项 | 结果 | 证据 |
| --- | --- | --- |

## 发现的问题
<每条附证据。送审方知道却没报的弱点单独标出。>

## 适用条件和失效条件
<哪些版本变化会让结论失效，比如规格改版、评测集改版。>

## 后续要求
<需要送审方或其他序列做的事。涉及其他序列的，由质量 +2 另发跨序列的需求包。>

## 事实依据

```

## 填写规则

- “可使用的结论原文”必填，而且要能直接引用。外联序列和送审方的上一级只认这一版。
- 缩小结论时，写清原结论的哪一部分不成立、为什么。
- 失效条件写成具体的版本号或事件。版本变化时，书记员据此提醒重新送审。
- 核查只看产物和结论，不调阅产出方的推理过程；评审尽量用和产出方不同的模型。

## 按结论类型的核查项

| 结论类型 | 核查项 |
| --- | --- |
| 效果类 | 候选数量和选择偏差、留出集重评、种子重复、基线预算是否相同、数据泄漏、成本 |
| 采纳类 | 日志是否覆盖整个观察期、合入记录是否属实、是否只统计了愿意用的人 |
| 可复现类 | 按命令重跑、误差是否在允许范围内 |
| 约束有效类 | 逐条重做越权测试、是否存在绕过路径 |
| 交付完整类 | 证据链接是否齐全、能否打开、是否对应到每条验收标准 |
