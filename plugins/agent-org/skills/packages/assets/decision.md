# 决策包模板（任一序列 +2 → 研究员）

研究员拍板的事都写成决策包，再由书记员建成决策工作项。决策包有两个来源，用同一份模板：

| 来源 | 谁写 | 工作项怎么建 | 渠道字段 |
| --- | --- | --- | --- |
| 决策队列 | 遇到超出授权的事的序列 +2 | 建成“待决定”，进决策队列；研究员定了以后流转到“已决定” | 决策队列 |
| 研究员主动发起 | 研究员在入口或聚焦会话里当场定下事情时，参与对话的那个 +2 | 建好后直接流转到“已决定” | 研究员主动发起 |

两条路流转到“已决定”时，流转表单都要求填写决定内容和决定人。要记的是会改变其他会话做法的决定，比如改目标、改验收标准、改规格、动资源或者新增约束；只影响当前会话内部做法的，不用记。

## 模板

```markdown
# 决策包：<事项>

- 包类型：决策包
- 渠道：决策队列 / 研究员主动发起
- 紧急程度：插队 / 今天 / 本周 / 可延后
- 默认处理：<到期还没决定时照什么办；没有写“无”>
- 发出方：<序列> +2（会话名）
- 接收方：研究员
- 关联工作项：<新建的决策工作项>
- 需要接收方做的事：拍板（决策队列）／确认记录无误（研究员主动发起）
- 回复期限：<截止时间>
- 上下文范围：只读本包；需要细节时按事实依据查

## 认知层
<一句话：需要研究员决定什么；研究员主动发起的，写已经定了什么。>

## 背景
<三到五句，只写做决定需要的信息。>

## 选项
| 选项 | 做法 | 代价 | 风险 |
| --- | --- | --- | --- |

## 建议
<推荐哪个选项，为什么。>

## 不决定的后果

## 待签版本
<涉及签字时，写文档链接和版本号，以及签字后要更新的字段，比如“项目”工作项的规格版本。>

## 决定
- 决定内容：
- 决定人：
- 理由：
- 在哪里定的：<决策队列，或者聚焦会话的会话名和日期>
- 受影响的工作项：<每个附工作项 ID>

## 事实依据

```

## 填写规则

- 决策队列来的决策包，“决定”一节先空着，研究员定了以后由书记员补上，并和流转表单里的决定内容、决定人一致。
- 研究员主动发起的决策包，“选项”和“建议”写谈话里比较过的做法；没比较过就写“无”，不补编选项。“决定”一节当场写全。
- 选项至少两个，其中一个可以是“不做”。
- 紧急程度决定在队列里的位置：“插队”的入口随时交研究员，其余每天交一次。默认处理写清楚，到期没人决定时就照它办，决策流转到“已过期”。
- 背景只写做决定需要的信息，详细材料放进事实依据。
- 涉及签字的需求文档、实验规格、评测协议、权限策略和证据标准，附待签版本的链接和版本号。
- “受影响的工作项”要写全。入口据此通知负责这些工作项的会话；漏写的，那些会话就不知道这件事已经定了。

## 各序列常见的决策包

| 序列 | 常见事项 |
| --- | --- |
| 产品 | 需求文档签字；试点结论签字；选题组合调整 |
| 算法 | 规格签字；超出授权的转向 |
| 工程 | 超预算；会影响多个项目的共享组件改动 |
| 基础设施 | 权限策略和身份方案签字；追加配额 |
| 质量 | 评测协议签字；证据标准变更；和送审方的争议 |
| 项目管理 | 台账结构、任务包模板等组织规则变更 |
| 外联 | 汇报节奏和模板调整；发给导师的材料确认 |
