# 飞书空间：模板、复制和绑定

## 两层空间

meegle 命令行建不了工作项类型、字段和流转；开放接口能建字段、关系、角色和条件视图，改模板时只能改状态的名称、类型和授权角色，改不了流转线和表单，也建不了类型。所以空间结构只能在网页上做，研究员自己点，或者由能操作浏览器的会话代点，步骤见 `build-space.md`。

为了不让每个项目都从头搭一遍，空间分两层：

- 模板空间：每个实验室或企业搭一次，默认叫 std_template，任务文件的 `feishu.template_space` 可以改名。它只放结构，不放工作项，不建条件视图。名字要和插件规则一字不差，用 `setup.py template --live` 核对到“可以当模板”为止。
- 项目空间：每个项目一个，用模板的“分享空间配置”复制，名字写进任务文件的 `feishu.meegle_space`。同一企业内实测过：类型和字段的系统标识原样带过去，流程、流转表单和详情页布局也带过去；流程模板 ID 会变，条件视图和空间置顶不带，每个项目空间各建一次。跨企业没有验证，不同版本之间（行业专版和其他版本、飞书项目和 Meegle）不互通。

模板改了以后，新复制的项目空间会带上；已经复制出去的不会跟着变，各自照绑定预览列出的清单补。

## 为什么要绑定

插件的规则文件只写设计，用中文名和英文标识描述，不带任何空间的 ID。type_key、field_key 和模板 ID 每个空间都不一样，复制出来的空间，模板 ID 也会变。每个项目在初始化时指定一个空间（任务文件的 `feishu.meegle_space`），再绑定一次：按名字或 `--map` 的指认，把规则里的类型和字段跟空间对上，把 type_key、api_name、模板 ID 和 field_key 记进项目的 `feishu/ids.json`。之后台账脚本只按这些键读写，空间里改名、插件改术语都不会断；键在空间里没了，下次绑定时报出来，重新指认。

## 步骤

1. 准备项目空间。任务文件写的空间还不存在的，照 `build-space.md` 从模板复制；企业里还没有模板的，先搭模板。研究员要是空间管理员，配置类型、字段和流程要管理员权限。空间名写进 `init --task` 用的任务文件的 `feishu.meegle_space`，重跑 `init --apply`；有同名空间的，写 simple_name 或 project_key。
2. 预览绑定：`setup.py feishu --target <项目目录> --live`。它按任务文件里的空间名精确查出 project_key 和 simple_name，导出字段字典，把规则里的类型和字段跟空间对上，读回模板 ID、研究员的 open_id（`lark-cli whoami`）和知识空间的 space_id，刷新知识库节点的标题，再按名字逐个查六个条件视图在不在。全是读操作；可选的几项读不到只提醒，不中断。空间里一种插件类型都对不上时，只提示从模板复制，不打印整份清单。
3. 按打印出来的 `feishu/migration.md` 逐节处理：
   - “要处理的问题”：名字不同的用 `--map` 指认；缺的先在模板里补，再在本空间照样补。
   - “每种类型要有的东西”：照它建类型、状态和流转、流转表单的必填字段、角色、字段和选项，每个状态的授权角色都设成“研究员”。几种类型都有的字段（序列、发出方等），在一个类型上建好，再用“复制至其他工作项”加到别的类型上。
   - “条件视图”：照表在项目空间建，标了置顶的放进空间置顶，步骤见 `build-space.md` 的“在项目空间补视图和置顶”。
   - “知识库节点”由书记员建：`ledger.py ensure-node <键>`，先预览再 `--apply`。它只认上一级下标题完全相同的节点；知识空间里已经有、只是名字不同的，先在网页上改成清单里的名字，否则会另建一个。命令行没有给节点改名的子命令；节点标题跟着节点文档的一级标题走。先读一遍节点文档：空的，书记员用 `lark-cli docs +update --doc <节点链接> --command overwrite --doc-format markdown --content - --as user`，用 heredoc 传入一行 `# <新名>`；有内容的在网页上改，不要覆盖。
   - “读回”：还没有知识空间的，研究员确认后由 setup 技能运行，或者研究员自己运行 `lark-cli wiki +space-create --name "<知识空间名>" --description "<一句话>" --as user`。
   - “网页上还要做的事”：详情页布局和项目详情页的标签页，在模板里做，复制时一起带过去；做完自己勾掉。
4. 改完重跑第 2 步，“要处理的问题”只剩已经知道、暂时不处理的项；加 `--apply` 写入。再重跑一次 `init --apply`，让 CLAUDE.md 和各角色拿到新的 ID。

以后空间有改动，或者任务文件换了空间，从第 2 步重做。任务文件写的空间和绑定的不一致时，台账脚本停下，等重新绑定。

## 六个条件视图

| 视图 | 工作项类型 | 条件 | 排序或显示 | 置顶 |
| --- | --- | --- | --- | --- |
| 决策队列 | 决策 | 状态 = 待决定 | 紧急程度（插队、今天、本周、可延后），再按截止时间 | 是 |
| 阻塞 | 同序列需求 | 状态 = 阻塞 | 名称、状态、序列、负责会话、阻塞原因、阻塞开始日期、截止时间、发出方 | 是 |
| 待验收 | 同序列需求 | 状态 = 待验收 | 名称、状态、序列、送审包、截止时间、负责会话、发出方 | 是 |
| 待核查 | 送审 | 状态 = 待核查 | 截止时间；名称、状态、核查深度、用途、截止时间、来源工作项、序列、发出方 | 是 |
| 序列看板 | 同序列需求 | 状态 ≠ 归档 | 看板，按序列分栏 | |
| 本周变化 | 同序列需求 | 更新时间 = 本周 | 更新时间倒序 | |

条件视图只能在网页上建。新建视图的对话框只能放进“个人”，要放进空间置顶，在左侧“空间置顶”的“+”里选“添加现有”。显示列在视图右上角“…”→“设置视图展示”里改，改完标题旁会出现“存在本地变更”，点“保存”才对所有人生效。项目详情页里要嵌工作项列表的，用“工作项视图”控件；“视图”控件要旗舰版。

## 实测过的坑

- 状态授权角色是必填的，界面上不设保存不了；插件要求全部设成“研究员”。命令行建工作项时不传角色人员，工作项上的“研究员”角色就没有人，所以 `ledger.py register` 建工作项时带上 `role_owners`（研究员 = 当前账号）。
- 每个状态流都自带“已终止”：删不掉，`list-state-transitions` 不返回它，终止不算一次流转。视图默认不显示已终止的工作项，MQL 不会自动排除，`ledger.py` 的查询都显式排除它。
- 日期字段写目标日期的 UTC 中午。meegle 原样保存毫秒时间戳，网页按浏览者的时区显示，空间时区要升级版本才能改：按东八区零点写的日期，美东的人看是前一天；写 UTC 中午，UTC-12 到 UTC+11 的人看到的都是同一天。
- MQL 的表名只认 type_key 或类型的中文名，不认 api_name；结果在 `data.<分组>[].moql_field_list` 里，状态是 `key_label_value_list`。时间条件用 ``RELATIVE_DATETIME_BETWEEN(`updated_at`, 'past', '7d')`` 这类写法。
- `workitem get` 不返回人员字段的值：决定人填了，`--fields '["_all"]'` 和指定 field_key 读回来都是空的。MQL 能读到，类型是 `user_value`，带 name_cn、name_en、user_key 和 email；`ledger.py` 读人员字段改用 MQL，只取名字。
- `workitem` 命令的 `--work-item-type` 接受 api_name、type_key 和中文名；`view search` 的 `--view-scope` 只认 type_key，而且 `--key-word` 必填、按名字模糊匹配（查“决策”会同时返回“决策队列”和别的视图），要按 `view_name` 精确比对。
- 工作项的网页链接是 `https://project.feishu.cn/<simple_name>/<api_name>/detail/<工作项 ID>`；simple_name 和 project_key 不能互换。
- 一个空间里，关联类字段只能指向一种工作项类型，所以“来源工作项”用单行文本存 ID；查的时候用 `=`，“转成的工作项”存多个 ID，用 `LIKE`。
- lark-cli 只读当前目录、`/tmp`、`~/files` 下的 `@文件`；macOS 的临时目录不在其中。`ledger.py` 一律用 `--content -` 从标准输入传正文。
- `docs +create` 只返回 docx 链接和 document_id，没有知识库节点；要用 `wiki +node-get --node-token <document_id>` 换出 node_token，主文档字段存 `/wiki/` 链接。
- 所有 agent 用的是研究员一个账号，流转的授权角色分不出是哪个会话；谁能流转由 hook 管。
- 新建工作项的模板 ID 必填，每个空间都不一样，绑定时读回。
- `workitem meta-types` 也列出空间里停用的系统类型（`is_disable` 为 1，比如需求、缺陷、版本、迭代），对它们查 `meta-fields` 会报找不到类型；导出字段字典时跳过它们。

## 没实测、先按推测处理的

- 自动化规则不通知操作者本人：没配过自动化，没测过。插件不依赖飞书通知，所以不影响运行；要用通知时先测一次。
- 研究员不是空间管理员时，当前负责人为空的工作项能不能流转。研究员是管理员时实测能流转；空间一般是研究员自己建的，就是管理员。
