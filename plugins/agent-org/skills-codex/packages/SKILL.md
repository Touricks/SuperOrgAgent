---
name: packages
description: 按智能体组织规范起草需求、交付、送审、验收和决策包；复用同一套包头、关系与验收规则。
---

先读项目 org/org.md 的包与关系表、当前工作项和主文档状态包。模板在 `.agent-org/templates/`，只选择适用的五类模板之一。详细原则、接口与例子按需读取 `../../skills/packages/references/` 下对应文件。

草稿写到 `packages/drafts/<序列>/`，先运行 `python3 -I .agent-org/bin/orgspec.py lint <草稿>`。交付和验收答复已有工作项，不另建同类项。执行关系必须给出来源工作项，质量结论由独立质量序列产生。跨序列、送审、决策经过 PMO；序列内包按既有派发图交接。

需求包、送审包的包头必须分别填写“业务产物写入范围”和“过程材料写入范围”。前者约束交付物，后者列出草稿、送审、交付和独立证据目录；不能把“只改一个业务文件”解释成禁止所有交回材料，也不能借过程材料扩大业务授权。与原始限制有冲突时，交发出方澄清后再登记。跨序列仍由承接方决定方法和内部权限，包头路径约定不代替它的判断。

需要登记时通过 entry 流程给唯一书记员发登记请求，提供路径、已有工作项、期望状态和摘要，不复制整个任务包进消息。同序列派活须先登记负责池位并流转为“执行中”；送审须先将来源任务流转为“待验收”，送审项为“待核查”。发送前 message 命令回读核对，接收方写业务产物或过程材料前再运行 start；不先执行再补记状态。
