# 独立正文发布

适用于已经承接的独立知识库正文创建、更新和移动任务。当前职责与委派以项目 `AGENTS.md` 为准，默认由书记员执行，明确委派可代办。普通内容任务先产出草稿并提交登记请求；不要因工具可用而自行发布。

## 写前核对对象

1. 读取原任务、源文件及其哈希，确认任务已经授权发布的正文和范围。沿用当前登记请求，不为了独立页面另建业务工作项。
2. 读取 `feishu/ids.json` 的 Wiki 绑定以及原工作项的主文档。核对真实空间 ID、父节点 ID 和它们与任务的关系，使用明确的目标父节点；绑定缺失或目标不符时停止。
3. 先查询父节点及其完整子节点列表。已有记录的文档按原 node token / document ID 核对，原位更新或移动，不复制替代。同名页需核对内容与来源，不能只按标题认领。
4. 读取当前飞书文档工具的帮助，确认输入和格式。使用相同账号、profile 和 `--as user`。创建、更新或移动都必须显式选择核对过的目标，不能依赖默认保存位置。
5. 在原任务的过程材料目录保存发布记录。预览只报告待执行操作；已有任务授权覆盖的正常发布无需再次询问。

## 发布与回读

独立正文可使用 `lark-cli docs +create`、`docs +update` 及对应 Wiki 节点工具。内容较长时使用工具支持的文件或标准输入方式，不把正文拼进 shell 字符串。命令参数以当前帮助为准，不猜测不存在的接口。

按任务要求保留原生高亮块、公式和表格。正文写入后回读文档内容，并查询 Wiki 节点核对空间、父节点、节点标题、文档标题及原生 ID。只读调用返回的节点和正文是验收依据，创建命令回显的参数不是回读。

项目类文档按项目规范保留标题下的原生三段高亮块；用对应格式或块读取确认其结构。数学公式必须核对表达式，表格核对行列和关键单元格，不能只检查页面存在。正文来源的语义不因格式转换而改变。

回读通过后，将两个独立页面的正式链接关联到原任务包、主文档或指定字段。工作项字段使用 `ledger.py update`，主文档追加交接说明使用 `ledger.py append`，保留既有工作项身份。不要整体覆盖主文档，也不要覆盖它的状态包和交接记录。

## 部分成功与续办

每一篇单独记录。第一篇成功、第二篇失败时，保留第一篇 ID 和回读证据，只续办第二篇。调用超时、返回缺少 ID 或连接断开时，记录 `unknown`，先核对远端；不能直接重新创建。

优先按已有 ID 查询；无 ID 时完整查询目标父节点，核对标题、来源和内容。发现多个可能对象时停止该项写入，交回具体候选和差异，不凭猜测选择或删除。只有确认没有创建结果后才能重试创建。

直接文档操作不经过台账锁，也不会自动写 `feishu/write-log.jsonl`。任务交接时明确单一执行者，当前执行者结束或交回前不由其他会话重复发布。连续两次写入失败停止该写入链，保存错误原文、logid 和已完成步骤。

## 发布记录示例

放在原任务约定的过程材料目录；以下是记录格式，不是新的权限配置。

```json
{
  "work_item_id": "原工作项 ID",
  "request_id": "原请求 ID",
  "actor": {"thread_id": "实际会话 ID", "role": "实际角色或 null"},
  "pages": [
    {
      "source_path": "正文相对路径",
      "source_sha256": "实际哈希",
      "space_id": "已核对的知识空间 ID",
      "parent_node_token": "已核对的父节点",
      "title": "正文标题",
      "status": "planned",
      "node_token": null,
      "document_id": null,
      "url": null,
      "readback_evidence": [],
      "error": null
    }
  ]
}
```

`planned` 为已保存预览，`unknown` 为写入结果待核对，`created` 为取得真实对象 ID，`verified` 为完成内容和父节点回读。记录真实角色，未绑定会话写 `null`；字段中的说明文字必须替换成实际值。页面列表支持多篇，不得把整个批次的一个成功回执套给所有页面。
