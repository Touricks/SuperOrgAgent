## 现有项目升级验收方法

验收由研究员明确指定的既有 PMO-p2-01 会话执行，保持其真实绑定身份。

验收覆盖**升级已经初始化的项目，以及完成原任务两篇独立正文的真实发布验证**。本轮没有新建空间、初始化知识目录、创建或重新绑定 21 个会话，也没有配置视图。

维护使用本仓库 `plugins/agent-org` 中的源码。先确认现有登记和独立文档发布已暂停，保存升级前的绑定、消息、知识目录 ID、工作项 ID 与回执快照，再从仓库根目录执行预览：

```bash
python3 -I plugins/agent-org/scripts/codex_upgrade.py upgrade --target '<已有项目绝对路径>'
```

确认预览只包含本地生成文件的变更后，在同一维护任务中应用：

```bash
python3 -I plugins/agent-org/scripts/codex_upgrade.py upgrade --target '<已有项目绝对路径>' --apply
```

若存在 `.new` 冲突，保留用户的项目补充规则并按冲突清单处理，不手工替换守卫、伪造会话身份或修改信任记录。升级中断时使用同一脚本的 `recover --target <目录>` 恢复完整旧版本。需要回退已完成的升级时使用 `rollback --target <目录> --backup <备份ID>`；文件已有后续修改时会停止，避免覆盖新内容。

升级后读取当前项目 `AGENTS.md`，运行 `.agent-org/bin/codex_runtime.py context`，再读取角色文件和 `.agent-org/operations/publishing.md`。原聊天无需重建，也不靠重命名或改角色获得写入能力。旧安装缓存中的技能版本可能仍是 codex.2，应以本次明确指定的新源码和已升级项目规则执行验收。
